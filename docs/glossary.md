
# Developer Glossary

A reference for common terminology used throughout Hello World.

## Git and Version Control

| Term | Meaning |
|---|---|
| Git | A distributed version control system used to track changes in files. |
| Version Control | A system for recording and managing changes to files over time. |
| Repository | A project directory whose contents and history are tracked by Git. |
| Commit | A recorded set of changes in a repository's history. |
| Branch | An independent line of development within a repository. |
| Main | A common name for a repository's default branch. |
| Merge | Combining changes from different branches. |
| Merge Conflict | A situation where Git cannot automatically combine changes. |
| Staging Area | The area where changes are prepared before committing. |
| Working Tree | The files currently checked out in a local repository. |
| HEAD | A reference to the currently checked-out commit. |
| Remote | A reference to another Git repository, often hosted online. |
| Clone | Creating a local copy of a remote repository. |
| Pull | Fetching changes from a remote repository and integrating them into the current branch. |
| Push | Sending local commits to a remote repository. |
| Fetch | Downloading changes and references from a remote repository without integrating them. |

## GitHub

| Term | Meaning |
|---|---|
| GitHub | An online platform for hosting Git repositories and collaborating on projects. |
| Fork | A GitHub-hosted copy of another repository under your account or organisation. |
| Pull Request | A proposal to review and merge changes from one branch into another. |
| Issue | A GitHub record used to track a task, bug, question or idea. |
| Review | An assessment of proposed changes in a pull request. |
| GitHub Pages | A GitHub service for publishing static websites. |
| Template Repository | A repository that can be used to generate new repositories with its existing files. |
| GitHub Actions | GitHub's automation platform for running workflows. |
| Organization | A shared GitHub account for managing repositories and collaborators. |

## Software Development

| Term | Meaning |
|---|---|
| Frontend | The part of an application users interact with directly. |
| Backend | The server-side part of an application. |
| HTML | A markup language used to structure web content. |
| CSS | A stylesheet language used to control presentation and layout. |
| JavaScript | A programming language commonly used to add functionality to websites. |
| Framework | A structured collection of tools and conventions for building software. |
| Dependency | External software or a package required by a project. |
| Deployment | Making an application or website available in a target environment. |
| Build | The process of preparing software for execution or distribution. |
| Debugging | Finding and fixing problems in software. |

## Commit Conventions

| Term | Meaning |
|---|---|
| Conventional Commits | A convention for writing structured commit messages. |
| `feat` | Introduces a new feature. |
| `fix` | Fixes a bug. |
| `docs` | Changes documentation. |
| `style` | Makes formatting or code-style changes without changing behaviour. |
| `refactor` | Restructures code without changing its external behaviour. |
| `perf` | Improves performance. |
| `test` | Adds or modifies tests. |
| `build` | Changes build systems or dependencies. |
| `ci` | Changes continuous integration configuration. |
| `chore` | Performs maintenance tasks. |
| `revert` | Reverses a previous commit. |

## Final Note

This glossary will expand as new concepts are introduced in the learning materials.

For detailed explanations, refer to the relevant documentation guides.
